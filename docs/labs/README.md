# Lab notebook

Use a dedicated Markdown note for each lab: setup, prerequisites, commands, expected output, actual results, problems and fixes, what to explain in a defence, and links to corresponding `report/` evidence. The executable code remains in `starter/`, `lab2/`, `lab3/`, `lab4/`, etc., as the handouts expect.

Suggested structure for a new lab note:

- Prerequisites and input data
- Goal and success criteria
- Reproducible commands
- Measurements and environment
- Verification (`pytest`, `SAME`, expected row counts, etc.)
- Issues encountered and resolutions
- Summary and open questions
- Report / AI log / submission checklist
